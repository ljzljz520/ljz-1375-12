# 商号史料关系库（shanghao-archive）

把“商号故事卡”做成**全栈史料关系库**：编辑端管理创立者、旧址、招牌与迁址事件；服务端保存
**陈述（statement）+ 出处（source）+ 不确定年代**；公开静态页联动**时间轴与地图**，打印 / 搜索 /
详情 / 地图共用同一份不可变发布版本。

零第三方运行依赖（仅 Node ≥ 20 内置模块）；地图前端通过 CDN 加载 Leaflet，离线时自动降级为
“时间轴与正文仍可完整阅读”。

## 快速开始

```bash
npm run seed     # 初始化示例数据并发布+构建首版（data/、dist/）
npm start        # http://localhost:8080  编辑台；公开站 /site/
npm run build    # 用“最新已发布版本”重建静态站
npm test         # 27 个验收测试（node:test）
```

编辑台右上角切换演示身份：

| 令牌 | 角色 | 能做什么 |
| --- | --- | --- |
| `tok-editor` | 林编辑 | 建卡 / 修订 / 合并 / 撤销合并 / 登记与撤权出处 / 批准引用影响 |
| `tok-approver` | 周审校 | **发布新版本、构建公开站** |
| `tok-promo` | 广告管理员 | **仅**维护商业推广标识 |
| `tok-viewer` | 访客 | 只读 |

## 数据模型（关键取舍）

- **卡片 = 稳定实体**（shop / person / place / sign），正文改动生成**不可变修订**（`R…`）。
- **陈述是最小事实单元**：`{ predicate, value, certainty, sourceIds[], pins{} }`
  - `certainty = inferred | confirmed | disputed`（推测 / 确证 / 争议）。
  - **互相冲突的创立日期是多条并列陈述**，各自带出处；系统从不取“最后编辑值”为唯一事实。
  - “推测变确证”是在新修订里改 `certainty`（可补新出处），旧陈述/旧修订原样保留。
- **历史地点解析**保留：原称 `rawName`、今释、候选点（可为空坐标）、解析精度
  （exact/building/block/street/district/unknown）与坐标精度。**缺坐标仍可读，地图不标点。**
- **年代解析** `parseHistDate`：`民国二十三年→1934`、`光绪三十三年→1907（候选）`、
  `一九五二年春→1952-03(季节)`、`光绪年间→区间`、`…前后→approximate`，无法定年返回
  `precision:'unknown'` 并在时间轴末位显示“年代待考”。
- **按时期拆记录**：商号卡上的 `periods[]`（如“南院门创业期 / 西大街时期”），同一商号可多次迁址，
  迁址是独立 `relocatedTo {fromPlaceId, placeId, 原称时间}` 事件，时间轴与地图按事件成线。

## 同名商号、合并与撤销合并

- **同名不一定是同一主体**：示例中 `H1` 南院门鼎丰号与 `H2` 东关鼎丰号是两张独立卡，系统不自动合并。
- 合并且只能由 editor **显式**操作，并带 `expectedRev` 乐观锁。迁移规则：
  1. 正文以存活卡为主，并入方陈述按“谓词+值+出处集合”去重后**迁移**（带 `migratedFrom*` 痕迹），
     冲突事实**并列保留，不覆盖**；异名进入别名。
  2. 所有指向并入方的入引用**改指存活卡**；旧引用所钉修订仍留在历史快照里。
  3. 合并前在**深拷贝**上模拟重定向并做循环预检；会成环则整笔拒绝、真实状态不变。
- **撤销合并**：迁移陈述退回原卡、入引用逆向恢复；被继续编辑过的陈述进入 `reviewNeeded` 人工核对清单。
- **两位编辑同时合并**：写操作串行化 + 双方 `expectedRev` 校验，结果恰为一胜一败（`200/409`）。

## 引用人物修订 → 影响清单 → 批准发布

1. 人物卡产生新修订后，引用该人物的商号卡不会静默跟随：`GET /api/impacts` 给出影响清单
   （stale=仍钉旧修订 / unpinned=从未钉版）。
2. editor 逐条 `update`（批准进新发布图）或 `keep`（旧卡保留引用版本；未钉版时钉到人物上一修订）。
3. 存在未处理影响时，approver **发布被阻止（409）**。
4. 发布生成不可变快照 `V…`（内容 SHA256）；公开页数据文件即 `assets/data-<hash>.js`。

## 出处与图片撤权

- 出处含权利状态 `unknown | licensed | withdrawn`。
- 撤权**不删除**出处：发布图中图片 `uri/embedded` 被剔除并标注“已撤权”，著录文字与陈述仍保留；
  旧发布版本不可变，撤权前的画面只存在于旧版。

## 商业推广标识

- 独立资源（`state.promo`），**仅 promo 角色**经 `PUT /api/cards/:id/promo` 维护；
  editor 在故事正文里夹带 `promo` 字段无效，正文修订也不会清除推广设置。

## 公开站点与“同一公开数据版本”

- `POST /api/releases`（approver）→ 不可变快照；`POST /api/build` 或 `npm run build`
  生成 `dist/`：SSR 的 `index.html`、`card-<id>.html`、`print-<id>.html`、
  `manifest.json` 与单一 `assets/data-<hash>.js`。
- 详情、**打印页（@media print）**、客户端**搜索索引**、Leaflet **地图**全部读同一个 data 文件，
  页脚标注版本号与哈希。
- 构建先写暂存目录、通过完整校验（环 / 缺失出处 / 缺失卡片 / 钉版不存在 / 数据漂移）后再原子切换；
  **任何失败都保留上一版 dist**，且不留暂存残留。

## 验收测试覆盖（`npm test`）

- 历史年代解析（民国 / 清纪年 / 汉字公元 / 季节 / 约词 / 未知排序）
- 冲突创立日期并列、乐观锁防覆盖、推测→确证、缺坐标可读
- 合并迁移规则、撤销恢复、入引用改指与逆向、类型限制、并发合并一胜一败
- 人物修订影响清单、发布阻塞、update/keep 两种批准、旧卡保留旧引用版本
- 图片撤权（旧版保留画面、新版剔除）、推广权限隔离
- 端到端循环引用（`partOf` 成环在保存与发布两处被阻断）
- 静态构建：同版数据文件 / 哈希；构建失败旧站保留；无发布版本拒绝构建
- HTTP 全流程（401/403/409、出处→卡片→发布→撤权→再发布→构建）
